# GeoNeural

How small can a terrain representation get before it stops being useful?

GeoNeural compares ways of storing a real elevation model by three measures at once: the bytes a
decoder needs, the height error against the reference, and the drainage network a routing
algorithm derives from the decoded surface. The test field is the 10 m terrain of southern Essen
and the Ruhr valley (DGM1, Geobasis NRW), a 10.24 km square with 1,050,625 nodes. The project also
covers a physics question that follows from it: can a learned update of the terrain keep the
balance of material it is supposed to model?

![Hillshaded 10 m terrain of southern Essen with the derived stream network](docs/figures/essen-terrain.png)

*The reference: DGM1 at 10 m, hillshaded, with D8 streams (contributing area of at least 0.05 km2) in blue. The Ruhr and Lake Baldeney cross the south; the straight lines on the lake are where routing crosses a flat water surface, which a bare-earth model cannot resolve.*

## Results in short

All numbers below were regenerated by this package; [docs/results.md](docs/results.md) has the
full tables, and the published reports in `results/` (`summary.json`, `candidates.json`,
`reproduced/`) hold the values they come from.

* **Height error is not drainage.** At a 1 m error bound the derived stream network overlaps the
  reference by only 22 % (Jaccard 0.219), 65 % of the reference stream cells are lost or moved, and
  the 268 catchments break into 2,798. Flow directions on
  slopes under 0.5 % already change in two of five cells at a 5 cm bound.
* **Sparse corrections are the cheap fix.** Exact heights on a band reaching one cell either side of
  the reference streams add 141,611 B to the 1 m product and raise the overlap from 0.22 to 0.68. Uniform
  precision needs 2.1 to 2.8 times the bytes for the same overlap.
* **Neural fields do not beat conventional codecs here.** Against a dense conventional sweep (grids
  of 10 to 640 m, each at 19 error targets), 9 of 103 learned candidates are not dominated on
  bytes, mean and maximum error together, and none has more than 11 % lower mean error than the best
  conventional candidate of the same size. Every network whose streams were measured keeps fewer of
  them. The smallest undominated hybrid is its own coarse grid plus 27 kB of weights that improve
  it by 2 mm.
* **Conservation should be built in.** A network that predicts one flux per cell face is the most
  accurate learned hillslope update (0.0048 m/yr, five seeds) and conserves to float32 rounding. A
  conservation penalty, swept over five orders of magnitude, at best trades accuracy for balance and
  stays about four orders of magnitude short of it.
* **Geology helps only a weak model.** The 1:100,000 geological map improves a held-out predictor by
  7 to 9 % over a misaligned copy of the same map in one of four setups and does nothing measurable when a network corrects a coarse grid.

## What is here

| Path | Contents |
|---|---|
| `src/geoneural/data` | Bounded downloads from the NRW services (WCS, WFS), receipts, preparation of the reference lattice and page pyramid, registration checks |
| `src/geoneural/codecs` | EAT1 pages, twelve conventional codecs, byte accounting, the dense conventional envelope |
| `src/geoneural/metrics` | Drainage routing and comparison, sparse corrections |
| `src/geoneural/neural` | Coordinate networks, latent grids and hybrids, architecture search, quantisation, decode latency |
| `src/geoneural/physics` | Landscape-evolution teacher and its audit, learned conservative closures, emulators, inverse and event-field studies |
| `src/geoneural/superres` | 10 m to 1 m super-resolution with an explicit observation operator |
| `src/geoneural/export` | Candidate table, summary, figures and the browser bundle |
| `native/` | Rust kernel for the landscape lab, compiled to WebAssembly, with parity tests against the Python fixtures |
| `web/` | Browser viewer, rate-quality chart and physics lab |
| `data/sample/` | The Essen tiles and geology extract, enough to rebuild everything above the neural layer |
| `results/` | Published reports, the candidate table and the summary every number in the docs comes from |
| `docs/` | [Data](docs/data.md), [methods](docs/methods.md), [results](docs/results.md) |

## Quick start

Python 3.12 and [uv](https://docs.astral.sh/uv/):

```bash
uv sync --extra codecs --extra fast
uv run pytest -q
uv run geoneural reproduce
```

`reproduce` rebuilds the Essen reference from the shipped tiles, checks its SHA-256, reruns the codec
comparison, the drainage metric and the corrections, and compares every number with the record in
`data/sample/essen-ruhr/expected.json`. It takes a few minutes on a CPU.

The neural and physics experiments need PyTorch and a GPU (`uv sync --all-extras`). Downloads,
atlases and checkpoints go to `GEONEURAL_HOME` (default `./.data`). Other regions are fetched from
the provider: `uv run geoneural fetch --preset rothaar-sauerland`, then
`uv run geoneural prepare --preset rothaar-sauerland`.

## Reproducing the published results

```bash
scripts/reproduce.sh
```

The script runs every experiment behind `results/` in order, then `publish` (copies the reports
into `results/reproduced/` with local paths removed), `candidates`, `summary`, `figures` and
`export-web`. `geoneural --help` lists every experiment; each writes one JSON report with its
configuration, input hashes, package versions and hardware. The super-resolution and distillation
steps run only when the 1 m data has been downloaded (see the comments in the script).

## Browser lab

```bash
uv run geoneural prepare --input data/sample/essen-ruhr/raw/input.json --out .data/atlases/essen-ruhr
uv run geoneural export-web
cd web && npm install && npm run wasm && npm run dev
```

The viewer shows the reference and seven decoded candidates on the real terrain, with error,
geology and stream overlays, a point inspector and cross-sections. The lab runs the landscape
kernel in a Web Worker: hillslope diffusion, the learned closures against their teacher, and a
material-contrast scenario with explicitly assumed coefficients. `export-web` writes the data it
reads to `web/public/bundle/`; the neural candidates appear once their decoded fields exist,
which the GPU steps of `scripts/reproduce.sh` write.

## Limitations

* One region is studied in depth. Six are prepared, but all of them were looked at during
  development, so there is no untouched confirmation region.
* The drainage measure is a routing comparison between two surfaces, not a hydrological model.
* The neural search had a fixed budget per family. A different search could find better networks;
  it would have to beat the dense conventional envelope on the same terms.
* Timings were taken on a shared workstation and are reported as ratios, not as absolute speed.
* The closure experiment is synthetic: a known nonlinear teacher on generated surfaces.
